# API Reference and Usage

Base URL (local dev): `http://localhost:5084`. No authentication (out of scope). All bodies are JSON. Errors use RFC 9457 Problem Details (`application/problem+json`).

## Run the service
```
dotnet run --project src/EventIngestion.Api --launch-profile http
```
Listens on `http://localhost:5084`. Quick check: `GET /health` returns `{"status":"ok"}`.

## Endpoints

### `POST /api/v1/readings` - ingest a batch
Body: JSON array of up to **50,000** readings.

| Field | Type | Rules |
|---|---|---|
| `deviceId` | string | required, 1-256 chars, case-sensitive |
| `timestamp` | string | required, ISO-8601 (`2026-10-08T09:00:01Z`; offsets are converted to UTC) |
| `value` | number | required, finite double |

```json
[
  { "deviceId": "sensor-0042", "timestamp": "2026-10-08T09:00:01Z", "value": 21.5 },
  { "deviceId": "sensor-0042", "timestamp": "2026-10-08T09:00:03Z", "value": 22.5 }
]
```

Every array element lands in exactly one bucket:

| Bucket | Meaning |
|---|---|
| `accepted` | applied to the device's window |
| `rejected.stale` | timestamp is 5 minutes or more behind server time (could never count) |
| `rejected.future` | timestamp more than 1 minute ahead of server time (clock-skew guard) |
| `rejected.invalid` | missing/null/wrong-typed field, bad date, non-finite number, empty or over-long id, non-object element |

**200 OK**
```json
{ "accepted": 2, "rejected": { "stale": 0, "future": 0, "invalid": 0 }, "total": 2 }
```

| Status | When |
|---|---|
| 200 | batch fully processed (even if some readings were rejected) |
| 400 | body is not a JSON array, or JSON is malformed/truncated |
| 413 | more than 50,000 readings, or body over the 16 MiB server cap |
| 415 | `Content-Type` is not `application/json` |

On 400/413 the readings parsed *before* the error remain applied; the problem body says how many:
```json
{ "status": 400, "title": "Batch not fully processed",
  "detail": "Malformed or truncated JSON. Readings before the error were applied.",
  "accepted": 1, "rejected": { "stale": 0, "future": 0, "invalid": 0 } }
```

### `GET /api/v1/devices/{deviceId}/aggregates` - rolling aggregates
Aggregates over readings with timestamp in `(now - 5 min, now]`, evaluated at request time.

**200 OK**
```json
{ "deviceId": "sensor-0042", "count": 2, "min": 21.5, "max": 22.5, "average": 22.0,
  "windowStart": "2026-10-08T09:00:00+00:00", "windowEnd": "2026-10-08T09:05:00+00:00" }
```
**404** with `title` `Unknown device` (never seen / already swept) or `No readings in window` (all readings aged out).

URL-encode the id (`plant%201`). A `/` inside an id cannot be addressed through the path (assumption; ids with slashes should be avoided).

### `GET /health`
`200 {"status":"ok"}` - cheap liveness check.

## Try it

### curl
```
curl -i http://localhost:5084/health

curl -i -X POST http://localhost:5084/api/v1/readings -H "Content-Type: application/json" \
  -d '[{"deviceId":"sensor-0042","timestamp":"<NOW-UTC-ISO>","value":21.5}]'

curl -i http://localhost:5084/api/v1/devices/sensor-0042/aggregates
```
Timestamps must be within the last 5 minutes (and not >1 minute ahead) or they are counted as stale/future. Use the current UTC time, e.g. `date -u +%Y-%m-%dT%H:%M:%SZ` (bash) or `(Get-Date).ToUniversalTime().ToString("o")` (PowerShell).

### Postman
Import `docs/api/postman/EventIngestion.postman_collection.json`. The collection variable `baseUrl` defaults to `http://localhost:5084`. The POST request's pre-request script fills `{{nowIso}}` and `{{nowIsoMinus1m}}` with current UTC times, so the sample bodies are always inside the window. Run the requests in order: Health, Ingest, Get aggregates, then the error cases.

### Bruno
Either use *Open Collection* on `docs/api/bruno` (native files, environment `local`), or *Import Collection > Postman* with the JSON above. Timestamps are generated by the pre-request scripts.

### VS Code REST Client / JetBrains HTTP client
Open `docs/api/requests.http` and click *Send Request* above each block.

### Load a large batch
`docs/api/` contains no generated payloads (kept out of the repo). To test the 50,000 limit, generate one with PowerShell:
```powershell
$now=(Get-Date).ToUniversalTime().ToString("o")
$items = 1..50000 | % { '{"deviceId":"d'+($_ % 1000)+'","timestamp":"'+$now+'","value":'+$_+'}' }
"[" + ($items -join ",") + "]" | Set-Content batch.json   # then: curl -X POST ... --data-binary "@batch.json"
```
(`batch.json` is git-ignored.)
